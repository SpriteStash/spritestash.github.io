Hellhound - Dark Fantasy Bestiary / Pack 03

Included

One quadruped demon boss. Eight actions in ten playback phases: Idle, Walk, Running Enter/Loop/Exit, Attack1 Claw, Attack2 Bite, Attack3 DashBite, Hurt and Death.

165 approved production Composed RGBA PNGs and 12 original spritesheet pages. Sheets arrange the same samples; they are not additional unique artwork. Original timing, alignment, manual edits, palette, skull, horns, mane, aura and soft alpha are preserved.

The native integrations use 165 sprite references packed losslessly into two 4096x4096 RGBA textures. Transparent margins are stored as per-frame registration data, without resampling production pixels.

Unity setup

Validated in Unity 6000.0.85f2, Built-in pipeline, Windows editor and Play Mode. Import the .unitypackage into a new or existing project. All product assets live under Assets/SpriteStash/Hellhound.

Open Scenes/SC_HellhoundDemo.unity and press Play. Select an action using the buttons. Stop loop finishes a complete Running cycle before the one-shot Exit. All actions restarts the approved showcase from the current position.

Drag Prefabs/PF_Hellhound.prefab into your scene. HellhoundPlayer.Play accepts Idle, Walk, Running, Attack1, Attack2, Attack3, Hurt or Death. RequestStop ends Running at a cycle boundary. PlayShowcase plays each phase once, then loops the complete sequence. The prefab does not enable showcase mode automatically.

autoReturnToIdle controls attack/Hurt recovery. externalClock lets your own update call Advance(milliseconds). Evaluate(milliseconds) inspects the current bank. SelectBank is a low-level phase inspector, not a replacement for the normal Play API. Library metadata preserves the exact frame intervals.

Sprites use the built-in sprite material; no custom shader or external package dependency is required. Input buttons use the included IMGUI demo only.

Unreal setup

Validated in Unreal Engine 5.8.3, Paper2D, Windows editor and PIE. Extract the project ZIP, open HellhoundDarkFantasyBestiaryPack03.uproject and enable Paper2D if prompted. No Python or C++ runtime dependency is required.

Open Maps/L_HellhoundOverview and press Play. Keys 1-8 select Idle, Walk, Running, Claw, Bite, DashBite, Hurt and Death. Space requests Stop loop; Tab restarts the complete showcase. Documentation/L_HellhoundGuide is the native quick-start guide. Maps/L_HellhoundSourceAssets displays the ten native phase Flipbooks and their texture sources.

To add the monster, migrate Blueprints/BP_HellhoundController with dependencies into your project and drag it into your level. Public functions PlayIdle, PlayWalk, PlayRunning, PlayAttack1, PlayAttack2, PlayAttack3, PlayHurt and PlayDeath select the eight actions. PlayState accepts indices 0-7 in that order. RequestStop exits Running at the full-cycle boundary. PlayShowcase resets to the recorded home position and starts the complete preview.

AutoPreview and DemoControls default off; the overview example turns them on. AutoReturnToIdle controls attacks/Hurt. The controller drives native PaperFlipbooks with exact millisecond durations; it does not substitute default fixed-FPS timing.

Exact production timing

Idle: 2500 ms, continuous loop. Walk: 1300 ms, continuous loop.

Running: Enter 360 ms once, Loop 400 ms indefinitely, Exit 450 ms once. A stop request during Enter still permits one full loop before Exit. Entry and Exit are never repeated inside the running loop.

Attack1 Claw: 720 ms once. Attack2 Bite: 960 ms once. Attack3 DashBite: 970 ms once. Hurt: 400 ms once. Death: 2480 ms once, including fall 880 ms and ash 1600 ms; final state absent.

Approved showcase: 10540 ms, 165 source samples; RunningLoop appears once. APNG encoding may merge identical adjacent frames without changing their total time. Review-only pauses of 500/600 ms are excluded from gameplay.

Dash and arrival position

Attack3 moves 448 production pixels, equal to 1.75 Unity units or 175 Unreal centimeters at the approved scale. This displacement is already inside the Composed frames. The owner follows the contract's per-frame root track while the drawing receives the equal inverse correction: the visual dash is never added twice.

The final position is retained when Attack3 recovers to Idle and when subsequent Hurt or Death is selected. Repeating Attack3 starts a new dash from the current owner position. The showcase resets to its recorded start only after Death completes. An interrupted dash preserves the last evaluated owner position; gameplay collision handling remains your responsibility.

Keep 256 pixels per Unity unit, 2.56 pixels per Unreal centimeter and physical scale 1. The standing art reference is [128,180] at native resolution. Per-phase production pivots and offsets are stored in PLAYBACK.json and the source placement contracts. These reproduce the approved drawing registration; they are not gameplay collision shapes. Do not recenter by changing bounds, tails or effects.

Pixels, effects and source files

Use approved Composed PNGs or their exact original spritesheets with white tint and alpha gain 1. Wine aura, spectral claw, skull bite, trails and ash are already baked. Do not add a second aura, rotate the effects again, refilter, repaint or stretch the frames.

Provenance contains editing sources for traceability only. Independent recomposition/filtering of those archived layers is not certified identical to approved Composed pixels. They are not native playback layers or extra production poses. Do not overlay them on Composed.

Death already contains all fall/ash effects and ends fully transparent. Do not add another dissolve or return to Idle after Death. GIF backgrounds and binary alpha belong to the viewer; use the production RGBA PNGs for soft transparency.

Scope and modification

This is an animation asset with playback examples. No enemy behavior logic, audio, gameplay hitboxes, navigation, damage system or complete combat game is included. Other engine versions, Unity URP/HDRP, UEFN, consoles/mobile and packaged builds are not validated.

Use the native controller's public Play functions and preserve its frame data when integrating your own gameplay. Regenerate assets only from the approved Composed pixel authority and exact contracts. Do not treat review pauses or the single-loop showcase as gameplay limits.
