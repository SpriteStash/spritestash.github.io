Demon Stalker - Dark Fantasy Bestiary / Pack 03

One common terrestrial demon predator. Seven actions: Idle, Walk, Running, Attack1 Double Claw Slashes, Attack2 Aerial Spinning Tail Strike, Hurt and Death. Original approved PNG pixels, cleaned edges, wine contour, palette, soft alpha and physical scale are preserved.

Quick start - Unity

Import the unitypackage into a Built-in project. Content is under Assets/SpriteStash/DemonStalker. Open Scenes/SC_DemonStalkerDemo and press Play. Buttons select the seven actions. Stop loop requests a complete-cycle exit; All actions plays the approved 9300 ms showcase.

Drag Prefabs/PF_DemonStalker into your scene for reusable playback. Call DemonStalkerPlayer.Play("Running") or Play("Attack2") to start Enter, then the indefinite Loop. Call RequestStop() to finish the current loop cycle and play Exit once, then Idle. A stop requested during Enter still permits one complete Loop. PlayShowcase() is the presentation sequence with one loop cycle per sustained action; it does not limit gameplay loops.

externalClock=false advances through Update. externalClock=true accepts Advance(milliseconds). Evaluate(milliseconds) samples the current phase; SelectBank(index) is available for inspecting the eleven native banks. autoReturnToIdle controls Attack1 and Hurt recovery. Death remains absent.

Quick start - Unreal

Extract the ZIP and open DemonStalkerDarkFantasyBestiaryPack03.uproject. Enable Paper2D. Open Maps/L_DemonStalkerOverview and press Play. Keys 1-7 select the seven actions, Space requests Stop loop and Tab restarts the automatic showcase. Open Documentation/L_DemonStalkerGuide for the native quick-start guide and Maps/L_DemonStalkerSourceAssets for the useful source gallery.

Drag Blueprints/BP_DemonStalkerController into your level. Named PlayIdle, PlayWalk, PlayRunning, PlayAttack1, PlayAttack2, PlayHurt and PlayDeath functions select actions; PlayState uses indices 0-6 in that order. RequestStop exits Running or Attack2 after the complete loop cycle. AutoPreview and DemoControls default off; AutoReturnToIdle defaults on. SetBank selects one of the eleven source phases for inspection. UpdateAction(DeltaSeconds) is driven by the Actor Tick. Do not also drive a second clock.

Use Asset Actions > Migrate on BP_DemonStalkerController with its dependencies. Keep the product folder. Migrate the gallery too if you want its optional inspectable views. No custom C++ or Python runtime dependency is required. Config contains demo startup/render settings, not gameplay input mappings; the reusable controller does not require a global project setting to play its sprites.

Exact timing, phases and controls

Idle: 1300 ms loop. Walk: 1900 ms loop. Running:Enter 360 ms once, Loop 480 ms indefinitely, Exit 540 ms once. Attack1: 890 ms once. Attack2:Enter 330 ms once, Loop 320 ms indefinitely, Exit 400 ms once. Hurt: 360 ms once. Death: 2420 ms once, comprising fall 820 ms and ash 1600 ms. The approved showcase is 9300 ms with 196 source samples; the encoded APNG merges unchanged adjacent images into 158 frames without changing timing.

Never repeat Enter or Exit inside a sustained Loop. Both stop requests take effect after a complete loop cycle, including the full tail rotation. A direct new Play action interrupts the current action; your game controls whether that interruption is allowed. No 600 ms inspection holds are included in runtime. Individual four-loop review previews are inspection examples, not a gameplay loop limit.

Registration and approved artwork

Use 256 pixels per Unity unit, 2.56 pixels per Unreal centimeter and physical scale 1. The action registrations reproduce the approved montage: Idle(256,418), Walk/Running/Hurt(320,482), Attack1(320,482), Attack2(384,546), Death(576,546), in each original canvas. Cropped native sprites store the original crop and anchor; changing bounding boxes must not recenter the monster. Source PIVOTS-AND-PLACEMENT.json and Contracts record all coordinates.

The Death corpse is intentionally 20 production pixels below its initial foot alignment. Do not snap it upward. Preserve existing approved edge truncations; do not repaint the tail, stretch the body, restore cleaned pixels, resmooth or repeat baked rotations.

The wine contour #7D183A at 40% and halo #570F28 at 10% are already baked into the approved Composed frames. Apply white tint and alpha gain 1. Components OR Composed, never both. The native controller uses Composed; separate optional components remain available in the raw-art download.

Attack1 has 16 body poses and 41 synchronized evaluated FX samples. Attack2 contains back/front main-cut and faint-trail layers; the phase contracts preserve their overlap, opacity and continuous loop. Death already includes the body, contour and fine windborne ash; do not add another dissolve. Production PNGs and APNGs preserve soft alpha; GIF palette transparency and its dark viewer matte must not become production artwork.

These are animation registrations, not a complete combat collision design. The reusable sprites have no gameplay hitbox, damage, enemy AI or movement-controller implementation. Add and tune collision shapes in your own gameplay context; the original visual alignment remains unchanged.

Download contents

The raw download contains 826 production animation PNG files and 57 original spritesheet pages across 47 components, including Composed alternatives and evaluated layers. Repeated/evaluated samples and alternative representations are not additional unique body poses. Original PNGs, sheets, contracts and source playback/pivot/contour metadata remain unchanged. ENGINE-PLAYBACK.json describes the native storage; it is separate from original playback.json. Source engine_tested=false records the art handoff before the Posts implementation, not the validation status of this integrated release.

The engine editions contain 196 registered sprite references in 11 native playback banks, stored losslessly in 2 atlas pages of 4096 x4096 pixels. Cropping and atlas packing preserve every visible pixel, alpha value and registration. Unity uses full-rectangle uncompressed sprites and scripted playback; Unreal uses Paper2D sprites, exact-duration flipbooks and a reusable Blueprint controller. Every phase is demonstrated by the supplied useful maps. Authoring history, cancelled dash attempts and obsolete quadrupedal claw attacks are excluded.

Compatibility and scope

Validated working editors: Unity 6000.0.85f2 Built-in and Unreal Engine 5.8.3 Paper2D on Windows. Final exported packages are separately imported/extracted and validated in clean projects before release. Other versions, URP/HDRP, UEFN and packaged platforms are not validated. No audio, enemy AI, complete combat system or gameplay collision shapes are included.
